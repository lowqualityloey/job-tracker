## 2. Axis 2 — what I checked and found correct

Not a list of complaints first, because these are the load-bearing claims a reviewer should be able to trust:

- **`event.newValue` is never parsed.** `grep -n newValue src/` returns prose only. The proof is structural:
  `externalWrite()` in `crossTabSync.test.tsx` dispatches `'{ not valid json — must not be parsed'` as the
  payload, and the test still expects the new row. Any implementation that decoded the event would surface a
  corrupt-data error there, so the requirement cannot be quietly dropped later.
- **Hooks are unconditional.** In `ApplicationsPage`, `useState`/`useMemo` sit above every early `return`; a
  hook after a `return` is a runtime crash that no test in this file would have caught on the first render,
  only on a loading→ready transition.
- **A failed re-read cannot serve a stale view.** `applyListResult` flips `status`, and all three pages branch
  on `status` before touching the array — the reason `applications` is left populated on error and it is still
  safe.
- **Fail-closed is proven at the byte level**: after the tab flips to `error` and *tries* to write, the test
  asserts `localStorage` still holds `schemaVersion: 999`. Not "the UI said no" — the bytes did not change.
- **The error state is not a dead end** (`0755adb`): a readable envelope arriving later returns the tab to
  `ready` and writes are accepted again. This test was written on a false premise first, and the false premise
  is recorded (Task Record §7) — a v1 build cannot write its way out of a v999 envelope, which is invariant 13
  working, not failing.
- **Test isolation**: `localStorage.clear()` is at file scope in a top-level `beforeEach`, which is the rule
  M2a learned the hard way (a `describe`-scoped reset does not apply to its sibling block).

## 3. Findings

### P1 — none open

Three P1-class process failures occurred and were repaired on-branch before publication (Task Record §7,
D-5/D-6/D-7): a commit made over two typecheck errors, a commit carrying two Greens under one message, and a
history rewrite that landed a fix two commits early and silently un-Red-ed a Red commit. All are visible in
the final history because it was re-audited commit by commit, not because they were avoided.

### P2 — recorded, deliberately not fixed on this branch

- **P2-1 · Storage events are not discriminated by `event.storageArea`.** A same-origin `sessionStorage` write
  with the *identical* key would trigger one spurious re-read. Accepted: the cost is a redundant read, and
  checking `storageArea === storage` would break the injectable `StorageLike` seam that every M2a fault test
  relies on. Revisit if the app ever shares the `job-tracker:` prefix across storage areas.
- **P2-2 · Overlapping re-reads are unordered.** Two `list()` calls in flight resolve in any order, and
  whichever finishes last wins. Harmless with a synchronous store, a real race with M3's HTTP client.
  **This is now M3's problem by name, not by surprise** — the HTTP adapter needs sequencing or an
  `AbortController` per read.
- **P2-3 · No test in this repository can fail a build for a missing focus ring or a 24 px hit target.** AC-10's
  CSS half was verified by reading `src/styles.css` (all three new controls have `min-height: 44px` and a
  `:focus-visible` ring). Same root cause as DEBT-15: nothing validates CSS at all.
- **P2-4 · Cross-tab behaviour has never run in a browser.** jsdom never fires `storage` on its own — the
  events are dispatched by hand, which models the browser's rule (never in the writer) but is still a model.
  The human's 30-second check is in the PR body; DEBT-01's residual widened rather than closed.

### P3 — nits, left alone deliberately

- `"Showing 1 of 1 applications"` is ungrammatical; pluralising off the total reads worse in the common case.
- When the zero-match state renders there are two polite regions on the page (`EmptyState`'s `aria-live` and
  the count's `role="status"`), so a screen reader may announce the count and then the empty state. Ordered
  and non-overlapping; a single announcement owner is a `pk:design` question, not a defect.
- `role="search"` wraps the status chips as well as the input. They do narrow the list; splitting the
  landmark would make the chip row homeless.
- `matchesQuery`'s `typeof value === 'string'` guard is what lets `notes?: string` be searched without a cast.
  A future non-string searchable field has to widen it, and the compiler will not say so.
